# 对话直达修订（选区即指令）— 设计与实现

> 2026-10-15

## 1. 设计原则

文档 AI 的核心架构：**一个内存文档模型，编辑器 UI 和 AI 工具面共享同一模型**，外加三条桥接模式（选区→引用块、发送前保存租约、revision 实时推送）。zpaper 不换编辑器底座（BlockNote 的 xl-ai/批注/协作已是差异化能力），而是把这套**交互协议**落到现有栈上。

## 2. 实现要点

| 机制 | zpaper v0.8 实现 |
|---|---|
| 选区 → 引用块 | `editor` 选区轮询 → ChatPanel「选区」引用 chip（可关闭、发送后消费） |
| 选区随消息进入对话上下文 | `context.docSelection` → ZCode agent 提示词 / provider 管线 system（`【用户当前选中的文档片段】`） |
| AI 结构化写文档 | `ai://local/doc-edit`：模型经 `applyDocumentEdits` 工具产出严格 JSON 修订计划（replace/insert/delete，find 必须逐字匹配原文） |
| AI 编辑实时可见 | 计划在渲染端直接应用到 BlockNote 编辑器（`updateBlock/insertBlocks/removeBlocks`），即时可见、Ctrl+Z 可撤销 |
| 修订痕迹 | 沿用 v0.6：保存 .docx 时块级 diff 经 SuperDoc SDK 写 Word 原生 `w:ins/w:del`（作者 zpaper） |
| 发送前保存租约 | （未实现）聊天读文档用打开时快照；本地单用户场景冲突面小，后续多文档时补 |

## 3. 数据流

```
用户选中文档文字 → ChatPanel 引用 chip（400ms 轮询选区）
        │ 发送（引用随 context.docSelection 一起上送；发送后 chip 消费）
        ▼
ZCode agent（plan 只读）或 provider 管线 —— 围绕选区回答
        │ 用户点回复下方「应用到文档」
        ▼
POST ai://local/doc-edit {instruction, proposal, docMarkdown, docSelection}
        │ 主进程 resolveProviderModel（无 provider → 演示 mock）
        │ generateText + toolChoice:"required" → applyDocumentEdits(ops)
        │ sanitizeDocEditPlan 校验（丢弃畸形 op、限 30 条、find≤2000 字）
        ▼
渲染端 applyDocEdits：逐 op 在编辑器内查找含 find 的块
  · replace：块内 inline 内容重建（保留被替换文字的样式；find 落在链接内则递归进链接保 href）
  · insert：锚块后插新段落；delete：整段删除
  · 单 op 失败不阻塞其余（failed 计数提示）
        ▼
用户在编辑器里看到修改（可撤销）→ 保存 → 原有管线写成 Word 修订
```

## 4. 涉及文件

- `src/shared/docEdits.ts` — 计划类型 + 校验 + 纯函数内容替换（主/渲染两端共享，22 个单测：`pnpm test:docedits`）
- `src/main/docEditPlan.ts` — `/doc-edit` 端点：provider 管线 + 演示 mock（`ZPAPER_FORCE_MOCK=1`）
- `src/main/main.ts` — 路由 + 两个冒烟（`ZPAPER_SMOKE_AI=1` 验端点；`ZPAPER_SMOKE_DOCEDIT=1` 经 automation hook 验真实编辑器应用）
- `src/renderer/docOps.ts` — 计划请求 + 编辑器应用器 + 选区读取
- `src/renderer/ChatPanel.tsx` — 引用 chip、「⤵ 应用到文档」动作
- `src/main/zcodeChatAgent.ts` / `chatWindow.ts` — 选区块注入提示词

## 5. 已验证

- `pnpm test:docedits`：22/22（跨节点样式保留、链接内替换、畸形计划过滤）
- `pnpm typecheck` / `pnpm build`：通过
- `ZPAPER_FORCE_MOCK=1 ZPAPER_SMOKE_AI=1`：`/doc-edit` 返回合法计划（演示模式按选区产出 replace）
- `ZPAPER_SMOKE_DOCEDIT=1`：真实编辑器 replace+insert+delete 全部应用，加粗样式保留（boldKept:true）

## 6. 已知取舍与后续

- 「应用到文档」是显式动作：对话默认只读建议，点按钮才落稿——与常见 inline AI 面板不同，但保留了"AI 改稿必须可见可撤销"的底线。
- replace 的 find 是整段连续文本匹配；跨段修改由计划模型拆成多条 op，规划器提示词已硬性约束。
- 表格单元格内的替换暂不生效（块级 content 非数组即跳过，计 failed）。
- 后续候选：①「应用到文档」结果接入变更面板（ChangesPanel）留痕；②SuperDoc 编辑面（Word 原生 UI）作为 .docx 的可选视图；③发送前保存租约。
